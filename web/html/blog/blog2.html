Docker & Containers: Ảo Hóa Tầng Hệ Điều Hành & Đóng Gói Microservices

Nhóm Kỹ sư Đám mây
Ngày đăng: 10/11/2026 DevOps & Docker

Tóm tắt chuyên đề: Containerization đã tạo ra cuộc cách mạng trong phương thức phát triển và phát hành phần mềm hiện đại. Thay vì mang theo cả một hệ điều hành khách (Guest OS) nặng nề hàng chục Gigabyte như máy ảo truyền thống, Docker tận dụng chung nhân hệ điều hành Linux (Host Kernel) để mang lại hiệu năng khởi động tức thì và mức tiêu thụ tài nguyên tối thiểu.

1. So Sánh Bản Chất: Virtual Machines (VMs) vs. Docker Containers

Để hiểu vì sao Docker lại trở thành tiêu chuẩn vàng trong triển khai microservices, chúng ta cần so sánh sự khác biệt căn bản về mặt kiến trúc ảo hóa:

  • Máy ảo (Virtual Machine - Hypervisor): Ảo hóa ở tầng phần cứng (Hardware-level Virtualization). Hypervisor (như VMware ESXi, Hyper-V, KVM) phân chia phần cứng vật lý và tạo ra các máy ảo độc lập. Mỗi máy ảo bắt buộc phải có một bản sao hệ điều hành khách hoàn chỉnh (Guest OS) bao gồm nhân kernel, thư viện hệ thống và tiến trình nền, dẫn đến dung lượng đĩa lớn (10GB - 50GB) và thời gian khởi động tính bằng phút.
  • Docker Container: Ảo hóa ở tầng hệ điều hành (OS-level Virtualization). Mọi container đều chạy trực tiếp trên nhân hệ điều hành chủ (Host OS Kernel) thông qua Docker Daemon. Nhờ vậy, container chỉ chứa ứng dụng và các thư viện phụ thuộc (dependencies) thực sự cần thiết, dung lượng ảnh chỉ từ vài chục Megabytes đến vài trăm Megabytes và có thể khởi động chỉ trong vài giây.

2. Ba "Trụ Cột" Công Nghệ Của Linux Kernel Tạo Nên Docker

Docker không phải là một công nghệ ảo hóa độc lập bí ẩn, mà là một lớp trừu tượng (abstraction layer) tinh vi tận dụng 3 tính năng cốt lõi của Linux Kernel:

  1. Linux Namespaces (Không gian tên cô lập): Đảm bảo sự cô lập hoàn toàn giữa các tiến trình của từng container. Các namespace quan trọng gồm:
    • PID namespace: Cô lập cây tiến trình, tiến trình trong container chỉ nhìn thấy chính nó như là PID 1.
    • NET namespace: Cô lập giao diện mạng, bảng định tuyến và danh sách cổng IP riêng biệt.
    • MNT namespace: Cung cấp điểm gắn hệ thống tệp riêng biệt cho container.
    • IPC & UTS namespaces: Cô lập giao tiếp liên tiến trình và tên máy chủ (hostname).
  2. Control Groups (Cgroups - Kiểm soát định mức tài nguyên): Cho phép Docker Daemon giới hạn và giám sát lượng tài nguyên vật lý mà mỗi container được phép sử dụng (CPU quotas, giới hạn RAM, băng thông I/O). Điều này ngăn ngừa tình trạng một container bị lỗi rò rỉ bộ nhớ làm sập toàn bộ hệ thống máy chủ.
  3. Union File System (Overlay2 - Hệ thống tệp lớp): Cho phép xếp chồng nhiều lớp tệp (layers) chỉ đọc (read-only) lên nhau và tạo một lớp ghi (read-write container layer) mỏng trên cùng. Các container chia sẻ chung các lớp image gốc giúp tiết kiệm hàng chục Gigabyte dung lượng đĩa.

3. Quản Trị Mạng Và Lưu Trữ Bền Vững Trong MyMiniCloud

Trong hệ thống MyMiniCloud, chúng ta áp dụng các nguyên tắc kỹ thuật Docker chuẩn mực:

  • Mạng Bridge cách ly (cloud-net): Thay vì dùng mạng bridge mặc định thiếu tính năng phân giải tên miền nội bộ, MyMiniCloud tạo một user-defined bridge network riêng với dải IP tách biệt. Các container có thể phân giải địa chỉ của nhau bằng tên dịch vụ (ví dụ: application-backend-server tự tìm thấy relational-database-server qua Docker DNS nội bộ).
  • Docker Named Volumes cho dữ liệu bất biến: Container về bản chất là phi trạng thái (stateless/ephemeral). Để dữ liệu cơ sở dữ liệu SQL Server không bị biến mất khi container khởi động lại hoặc recreate, named volume mycloud_mssql-data được gắn trực tiếp vào /var/opt/mssql. Tương tự, MinIO sử dụng mycloud_minio-data và Grafana dùng mycloud_grafana-data.

4. Quản Lý Vòng Đời Bằng Docker Compose

Với một hệ thống gồm 9 nhóm dịch vụ đa dạng từ Web Nginx, API Flask, SQL Server, MinIO đến Prometheus, việc chạy các lệnh docker run thủ công là không khả thi và dễ xảy ra sai sót. Docker Compose đóng vai trò như bản thiết kế hạ tầng dạng mã nguồn (Infrastructure as Code - IaC), giúp:

  • Khai báo quan hệ phụ thuộc giữa các dịch vụ (depends_on và healthcheck).
  • Tách biệt cấu hình nhạy cảm (mật khẩu SA, khóa bí mật) ra tệp biến môi trường .env.
  • Khởi động hoặc dừng toàn bộ hệ sinh thái chỉ bằng một lệnh duy nhất: docker compose up -d.
