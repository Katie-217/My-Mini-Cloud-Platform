Giới thiệu chuyên đề: MyMiniCloud không phải là một ứng dụng nguyên khối (monolith) giả lập, mà là một hệ thống phân tán thực thụ gồm 9 nhóm dịch vụ container hóa độc lập. Mỗi dịch vụ đảm nhiệm một trách nhiệm chuyên biệt, được kết nối an toàn qua mạng bridge và được phối hợp nhịp nhàng thông qua Nginx Reverse Proxy.

1. Kiến trúc tổng thể & luồng di chuyển của Request

Điểm cốt lõi trong thiết kế của MyMiniCloud là mô hình Single Point of Entry (Cổng tiếp nhận duy nhất). Người dùng từ trình duyệt bên ngoài chỉ cần truy cập vào cổng 80 của máy chủ Host. Tất cả các dịch vụ nội bộ khác (Flask API :8081, SQL Server :1433, Keycloak :8080) đều được ẩn sau mạng cloud-net và không cần phơi bày cổng ra Internet:

  • Truy cập Portal (/) và Blog (/blog/): Proxy chuyển hướng tới một trong hai máy chủ web Nginx (web-frontend-server1 hoặc web-frontend-server2) theo thuật toán xoay vòng Round Robin.
  • Truy cập ứng dụng quản lý sinh viên (/app/): Proxy phục vụ tệp HTML/CSS/JavaScript tĩnh từ web server; sau đó trình duyệt của người dùng gửi các lời gọi AJAX tới đường dẫn /api/*.
  • Gọi REST API (/api/*): Proxy tiến hành loại bỏ (strip) tiền tố /api/ và chuyển tiếp nguyên vẹn method và payload JSON tới container application-backend-server:8081.
  • Xác thực danh tính (/auth/*): Proxy giữ nguyên đường dẫn và forwarded headers chuyển tiếp đến authentication-identity-server:8080 (Keycloak).

2. Cơ chế cân bằng tải Round Robin giữa 2 Web Replicas

Nhằm mô phỏng tính sẵn sàng cao (High Availability), hệ thống khởi chạy hai bản sao máy chủ web tĩnh độc lập:

upstream web_pool { zone web_pool 64k; server web-frontend-server1:80 resolve max_fails=2 fail_timeout=5s; server web-frontend-server2:80 resolve max_fails=2 fail_timeout=5s; }

Khi người dùng nhấn Reload hoặc chạy thử nghiệm tải trong Portal Control, Nginx phân phối luân phiên từng request đến Server 1 rồi đến Server 2 với tỷ lệ cân bằng 50/50 hoàn hảo.

3. Tích hợp đa dịch vụ: SQL Server, MinIO S3, Keycloak PKCE & Prometheus

Khác với các đồ án đơn lẻ, MyMiniCloud chứng minh khả năng liên kết sâu giữa các thành phần doanh nghiệp:

  1. Lưu trữ quan hệ (RDBMS): Container database-sqlserver-2022 chạy SQL Server 2022 trên Linux, lưu trữ danh mục sinh viên và điểm số theo mô hình ACID chuẩn mực.
  2. Lưu trữ phi cấu trúc (Object Storage): Container object-storage-server chạy MinIO S3 tương thích AWS S3 API, tiếp nhận ảnh đại diện và hồ sơ sinh viên tải lên qua bucket profile-pics.
  3. Bảo mật phân quyền (IAM SSO): Container authentication-identity-server cung cấp Keycloak realm mini-cloud, hỗ trợ đăng nhập một lần (Single Sign-On) và cấp phát JWT token có chữ ký số.
  4. Giám sát hạ tầng (Observability): Bộ đôi Prometheus (:9090) và Grafana (:3000) tự động cào metrics từ cAdvisor và Node Exporter, vẽ biểu đồ CPU, RAM, Network I/O thời gian thực.

4. Bảng bóc tách chi tiết 9 nhóm dịch vụ MyMiniCloud

Nhóm dịch vụ Container Service FQDN nội bộ Cổng nội bộ Vai trò kiến trúc
Nhóm 1: Web Hosting web-frontend-server1, 2 web.cloud.local 80 Cụm Nginx Web Replicas phục vụ Portal, App, Blog
Nhóm 2: Application API application-backend-server app-backend.cloud.local 8081 Flask REST API nghiệp vụ quản lý sinh viên
Nhóm 3: SQL Database database-sqlserver-2022 sqlserver.cloud.local 1433 Cơ sở dữ liệu quan hệ SQL Server 2022 Linux
Nhóm 4: Object Storage object-storage-server minio.cloud.local 9000, 9001 MinIO S3 Object Storage lưu trữ ảnh đại diện
Nhóm 5: Identity IAM authentication-identity-server keycloak.cloud.local 8080 Keycloak SSO Realm mini-cloud (OIDC / OAuth 2.0)
Nhóm 6: Reverse Proxy api-gateway-proxy-server gateway.cloud.local 80 Cổng tiếp nhận duy nhất & Cân bằng tải Round Robin
Nhóm 7: Internal DNS dns-bind9-server dns.cloud.local 1053 Phân giải tên miền cục bộ zone cloud.local
Nhóm 8: Metrics Prometheus monitoring-prometheus-server prometheus.cloud.local 9090 Thu thập và lưu trữ time-series metrics
Nhóm 9: Dashboard Grafana monitoring-grafana-dashboard-server grafana.cloud.local 3000 Trực quan hóa Dashboard hiệu năng máy chủ
