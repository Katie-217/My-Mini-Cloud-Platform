Bên Trong MyMiniCloud: Cách Một Hệ Thống 9 Dịch Vụ Vận Hành Thực Tế

Khám phá chi tiết luồng xử lý end-to-end: Reverse Proxy cân bằng tải Round Robin, Flask REST API, SQL Server 2022, MinIO S3, Keycloak PKCE và chu trình giám sát Prometheus.

Nhóm Kỹ sư Đám mây
10/11/2026 Distributed Systems
Giới thiệu chuyên đề: MyMiniCloud không phải là một ứng dụng nguyên khối (monolith) giả lập, mà là một hệ thống phân tán thực thụ gồm 9 nhóm dịch vụ container hóa độc lập. Mỗi dịch vụ đảm nhiệm một trách nhiệm chuyên biệt, được kết nối an toàn qua mạng bridge và được phối hợp nhịp nhàng thông qua Nginx Reverse Proxy.

1. Kiến Trúc Tổng Thể & Luồng Di Chuyển Của Request

Điểm cốt lõi trong thiết kế của MyMiniCloud là mô hình Single Point of Entry (Cổng tiếp nhận duy nhất). Người dùng từ trình duyệt bên ngoài chỉ cần truy cập vào cổng 80 của máy chủ Host. Tất cả các dịch vụ nội bộ khác (Flask API :8081, SQL Server :1433, Keycloak :8080) đều được ẩn sau mạng cloud-net và không cần phơi bày cổng ra Internet:

  • Truy cập Portal (/) và Blog (/blog/): Proxy chuyển hướng tới một trong hai máy chủ web Nginx (web-frontend-server1 hoặc web-frontend-server2) theo thuật toán xoay vòng Round Robin.
  • Truy cập ứng dụng Quản lý Sinh viên (/app/): Proxy phục vụ tệp HTML/CSS/JavaScript tĩnh từ web server; sau đó trình duyệt của người dùng gửi các lời gọi AJAX tới đường dẫn /api/*.
  • Gọi REST API (/api/*): Proxy tiến hành loại bỏ (strip) tiền tố /api/ và chuyển tiếp nguyên vẹn method và payload JSON tới container application-backend-server:8081.
  • Xác thực danh tính (/auth/*): Proxy giữ nguyên đường dẫn và forwarded headers chuyển tiếp đến authentication-identity-server:8080 (Keycloak).

2. Cơ Chế Cân Bằng Tải Round Robin Giữa 2 Web Replicas

Nhằm mô phỏng tính sẵn sàng cao (High Availability), hệ thống khởi chạy hai bản sao máy chủ web tĩnh độc lập: 

upstream web_pool {
    zone web_pool 64k;
    server web-frontend-server1:80 resolve max_fails=2 fail_timeout=5s;
    server web-frontend-server2:80 resolve max_fails=2 fail_timeout=5s;
}

Mỗi request gửi đến máy chủ web được gắn kèm header X-Web-Server phản ánh chính xác hostname của container đang xử lý. Khi người dùng thực hiện reload hoặc gửi yêu cầu trên ứng dụng, lượng tải sẽ luân phiên chia đều 50/50 giữa 2 server.

3. Tích Hợp Đa Dịch Vụ: Cơ Sở Dữ Liệu, S3 và Bảo Mật OIDC

Mảnh ghép nghiệp vụ trung tâm của MyMiniCloud nằm ở container application-backend-server viết bằng Python 3.12 Flask:

  1. Tương tác SQL Server 2022 qua ODBC Driver 18: Backend sử dụng thư viện pyodbc kết nối trực tiếp đến database studentdb. Mọi thao tác CRUD sinh viên đều thực thi các câu lệnh T-SQL chuẩn mực trên bảng dbo.students, đảm bảo tính toàn vẹn dữ liệu (ACID).
  2. Lưu trữ đối tượng với MinIO S3: Thay vì lưu ảnh và tài liệu trực tiếp vào hệ thống tệp của container (gây đầy ổ và mất dữ liệu khi scale), backend tích hợp thư viện MinIO SDK. Tệp ảnh đại diện được tải vào bucket profile-pics, hồ sơ PDF tải vào bucket documents. Vì các bucket này ở chế độ private, backend hoạt động như một Secure Gateway kiểm duyệt quyền truy cập trước khi sinh download stream.
  3. Xác thực OIDC với PKCE (Proof Key for Code Exchange): Thay vì dùng flow Implicit đã lỗi thời hoặc truyền client secret ở frontend, ứng dụng sử dụng flow Authorization Code kèm PKCE S256. Trình duyệt tự sinh code_verifier và code_challenge, gửi xác thực qua Keycloak, nhận Authorization Code và đổi lấy JWT Access Token. Backend Flask kiểm tra tính hợp lệ của token qua chữ ký RS256 và endpoint JWKS của Keycloak.
