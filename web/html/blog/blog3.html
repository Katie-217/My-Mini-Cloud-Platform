Giới thiệu chuyên đề: MyMiniCloud không phải là một ứng dụng nguyên khối (monolith) giả lập, mà là một hệ thống phân tán thực thụ gồm 9 nhóm dịch vụ container hóa độc lập. Mỗi dịch vụ đảm nhiệm một trách nhiệm chuyên biệt, được kết nối an toàn qua mạng bridge và được phối hợp nhịp nhàng thông qua Nginx Reverse Proxy.

1. Kiến trúc tổng thể & luồng di chuyển của Request

Điểm cốt lõi trong thiết kế của MyMiniCloud là mô hình Single Point of Entry (Cổng tiếp nhận duy nhất). Người dùng từ trình duyệt bên ngoài chỉ cần truy cập vào cổng 80 của máy chủ Host. Tất cả các dịch vụ nội bộ khác (Flask API :8081, SQL Server :1433, Keycloak :8080) đều được ẩn sau mạng cloud-net và không cần phơi bày cổng ra Internet:

  • Truy cập Portal (/) và Blog (/blog/): Proxy chuyển hướng tới một trong hai máy chủ web Nginx (web-frontend-server1 hoặc web-frontend-server2) theo thuật toán xoay vòng Round Robin.
  • Truy cập ứng dụng quản lý sinh viên (/app/): Proxy phục vụ tệp HTML/CSS/JavaScript tĩnh từ web server; sau đó trình duyệt của người dùng gửi các lời gọi AJAX tới đường dẫn /api/*.
  • Gọi REST API (/api/*): Proxy tiến hành loại bỏ (strip) tiền tố /api/ và chuyển tiếp nguyên vẹn method và payload JSON tới container application-backend-server:8081.
  • Xác thực danh tính (/auth/*): Proxy giữ nguyên đường dẫn và forwarded headers chuyển tiếp đến authentication-identity-server:8080 (Keycloak).

2. Cơ chế cân bằng tải Round Robin giữa 2 Web Replicas

Nhằm mô phỏng tính sẵn sàng cao (High Availability), hệ thống khởi chạy hai bản sao máy chủ web tĩnh độc lập:

upstream web_pool { zone web_pool 64k; server web-frontend-server1:80 resolve max_fails=2 fail_timeout=5s; server web-frontend-server2:80 resolve max_fails=2 fail_timeout=5s; }

Khi cả hai replica khỏe và dùng cấu hình cùng trọng số, Nginx phân phối request theo Round Robin. Một chuỗi 20 request kiểm thử riêng nhận 10 request ở mỗi replica; các request từ trình duyệt, healthcheck hoặc replica lỗi có thể làm số đếm quan sát khác đi.

3. Tích hợp đa dịch vụ: SQL Server, MinIO S3, Keycloak PKCE & Prometheus

Khác với các đồ án đơn lẻ, MyMiniCloud chứng minh khả năng liên kết sâu giữa các thành phần doanh nghiệp:

  1. Lưu trữ quan hệ (RDBMS): Service relational-database-server chạy SQL Server 2022 trên Linux. Dữ liệu nằm trong studentdb.dbo.students, được lưu bền vững ở volume mycloud_mssql-data gắn vào /var/opt/mssql. Student App gọi Flask API để đọc và cập nhật dữ liệu.
  2. Lưu trữ phi cấu trúc (Object Storage): Service object-storage-server chạy MinIO S3, lưu ảnh trong bucket profile-pics và PDF trong documents. Hai bucket private; giao diện tải file qua Flask API.
  3. Xác thực (IAM SSO): Service authentication-identity-server cung cấp Keycloak realm chung 521H0092-523H0065 cho hai thành viên, với client public flask-app, hai user demo sv01/sv02 và Authorization Code + PKCE. Flask xác minh JWT tại /api/secure; CRUD và file API vẫn công khai trong bản demo local.
  4. Giám sát hạ tầng (Observability): Prometheus (:9090) scrape Node Exporter và Blackbox Exporter. Blackbox kiểm tra hai web replica; Grafana (:3000) truy vấn Prometheus để vẽ CPU, RAM và Network. CPU/RAM thuộc Linux VM của Docker Desktop, network thuộc namespace Node Exporter.

4. Bảng bóc tách chi tiết 9 nhóm dịch vụ MyMiniCloud

Nhóm dịch vụ Compose service Bind9 / Docker DNS Cổng nội bộ Vai trò kiến trúc
Nhóm 1: Web Hosting web-frontend-server1, web-frontend-server2 web.cloud.local → gateway; Docker DNS gọi riêng từng replica 80 Cụm Nginx Web Replicas phục vụ Portal, App, Blog
Nhóm 2: Application API application-backend-server app-backend.cloud.local 8081 Flask REST API nghiệp vụ quản lý sinh viên
Nhóm 3: SQL Database relational-database-server relational-database-server (Docker DNS; chưa có record Bind9 riêng) 1433 Cơ sở dữ liệu quan hệ SQL Server 2022 Linux
Nhóm 4: Object Storage object-storage-server minio.cloud.local 9000, 9001 MinIO lưu ảnh và PDF trong hai bucket private
Nhóm 5: Identity IAM authentication-identity-server keycloak.cloud.local 8080 Keycloak realm 521H0092-523H0065 (OIDC / OAuth 2.0)
Nhóm 6: Reverse Proxy api-gateway-proxy-server web.cloud.local 80 Cổng tiếp nhận duy nhất & Cân bằng tải Round Robin
Nhóm 7: Internal DNS internal-dns-server ns.cloud.local 53 UDP/TCP (host: 1053) Phân giải tên miền cục bộ zone cloud.local
Nhóm 8: Metrics Prometheus monitoring-prometheus-server monitoring-prometheus-server (Docker DNS; chưa có record Bind9 riêng) 9090 Thu thập và lưu trữ time-series metrics
Nhóm 9: Dashboard Grafana monitoring-grafana-dashboard-server grafana.cloud.local 3000 Trực quan hóa Dashboard hiệu năng máy chủ

Bind9 quản lý zone cloud.local; Docker DNS phân giải tên service trong cloud-net. Tên container thực tế do Compose sinh theo dạng mycloud-<service>-1. Web tĩnh không truy vấn database; Student App truy cập dữ liệu qua /api/students-db.
